# OctoAcme Project Management Docs

This repository contains the project management process guidance used by OctoAcme. The documents below provide a shared operating model for initiation, planning, execution, delivery, risk management, and continuous improvement.

## Project management process summary

OctoAcme follows a structured but lightweight project lifecycle: initiation to define the problem, stakeholders, and success metrics; planning to break work into milestones and backlog items; execution to deliver in short, testable increments; release to validate and deploy changes; and retrospective to capture learning and improve the process. The approach emphasizes customer value, clear ownership, iterative delivery, and decisions informed by measurable outcomes.

The operating model is built around defined roles and communication rhythms. Product Managers define outcomes and priorities, Project Managers coordinate schedules and dependencies, developers implement features and maintain quality, QA validates acceptance criteria, and stakeholders provide input and approvals. Teams rely on project boards, standups, weekly syncs, demos, and escalation paths to keep work visible and unblock dependencies quickly.

Quality is treated as a core part of delivery. The process calls for unit, integration, and smoke testing where appropriate, with CI validation, security scanning, and manual QA for feature acceptance. Releases require passing checks, release notes, rollback plans, and post-deploy verification. Retrospectives and continuous improvement are built into the workflow so action items become part of the team’s ongoing operating model.
